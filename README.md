# Q-SHIELD: reproducibility package

Code, raw measurements and manuscript source for the paper
*Q-SHIELD: A CRYSTALS-Kyber and Dilithium-Secured Lightweight Authentication and Intrusion Detection Framework for Post-Quantum Vehicle-to-Everything (V2X) Communication Networks*.

Every number, table and figure in `paper/main.tex` is generated by the scripts in this repository from files in `results/`. Nothing is typed in by hand.

## What is in the paper and where it comes from

| Paper item | Produced by | Raw output |
|---|---|---|
| Table I (primitive latency, sizes), Fig. 4a-b | `python -m qshield.crypto_bench` | `results/crypto_bench.json`, `results/crypto_bench_raw.npz` |
| Table II (full handshake), Fig. 4c | `python -m qshield.handshake_bench` | `results/handshake_bench.json`, `results/handshake_bench_raw.npz` |
| Beacon verification throughput (text) | `python -m qshield.pipeline_bench` | `results/pipeline_bench.json` |
| Table III (beacon sizes), Fig. 5 | `python -m qshield.overhead` | `results/overhead.json` |
| Tables IV-VII (IV detection, V ablation, VI per-class, VII features), Fig. 6, IDS numbers in text | `python -m qshield.ids` (two runs: `--name ids` with history features, `--name ids_single` with single-message fields only) | `results/ids_results.json`, `results/ids_roc_curves.npz`, `results/ids_single_results.json`, `results/ids_single_roc_curves.npz` |
| LaTeX tables and macros | `scripts/make_tables.py` | `paper/generated/*.tex` |
| PNG figures 4-6 (`fig4_latency`, `fig5_channel_load`, `fig6_roc`) | `scripts/make_figures.py` | `paper/figures/*.png` |
| PNG figures 1-3 (diagrams) | `paper/figure_sources/*.tex` | `paper/figures/*.png` |

The protocol itself is in `src/qshield/protocol.py` (handshake, certificates, beacon signing and verification) and the cipher suites are in `src/qshield/suites.py` (ML-KEM-768 and ML-DSA-65 through liboqs; ECDH/ECDSA P-256 and RSA-3072 through `cryptography`).

## Quick start (Linux)

Requirements: gcc, cmake, git, Python 3.11+, OpenSSL development headers, and a LaTeX installation with `IEEEtran` (`texlive-publishers`, `texlive-latex-extra`, `texlive-fonts-recommended`) to build the PDF.

```bash
git clone <this repository>
cd qshield
make setup        # builds liboqs 0.16.0 locally, creates .venv, installs pinned Python packages
make test         # runs the protocol and tamper tests for all three cipher suites
make bench        # crypto, handshake, pipeline and overhead measurements
```

The IDS experiment needs the dataset (see next section). Then:

```bash
make ids          # trains and evaluates the detectors, regenerates tables and figures
make paper        # builds paper/main.pdf
```

`make all` (or `bash scripts/run_all.sh`) runs everything in sequence and skips the IDS step with a message if the dataset file is missing.

The scripts set `OQS_INSTALL_PATH` and `LD_LIBRARY_PATH` through `scripts/env.sh`. If you run Python by hand, `source scripts/env.sh` first. Without it the liboqs Python wrapper tries to download and build its own copy.

## Dataset for the IDS experiment

The IDS experiment uses the merged VeReMi Extension CSV by Oumsaad et al., Mendeley Data, DOI 10.17632/k62n4z9gdz.1 (https://data.mendeley.com/datasets/k62n4z9gdz/1), which combines the 39 simulations of Kamel et al. into 3,194,808 rows. The file is not included here.

1. Download the CSV and save it as `data/veremi_extension.csv` (the file is `mixalldata_clean.csv` inside the Mendeley archive).
2. Inspect it: `python scripts/inspect_dataset.py data/veremi_extension.csv 20000`.
3. The two configurations used in the paper are already set up:
   - `configs/dataset.json` (`--name ids`): the per-message fields plus 15 history features computed by `src/qshield/features.py`. History is keyed by `senderPseudo`, the only identity a receiver sees, and compares each message with the same pseudonym's previous message (time gap, displacement, implied speed, speed and acceleration change, heading consistency, prediction error). Features are computed on the full data before any subsampling.
   - `configs/dataset_single.json` (`--name ids_single`): per-message fields only. This is the ablation.
   Both use the label column `class` (0 = genuine, everything else an attack), a split grouped by `sender` so that no vehicle appears in more than one of train, validation and test (70/10/20), five seeds, and a stratified subsample of 400,000 messages (`max_rows`; set it to `null` to use all rows). The identifier and timestamp columns in `drop_columns` are never features.
4. Run `make ids`. It runs both configurations, then regenerates the tables and figures.

On Windows, or on any machine without liboqs, the IDS step does not need liboqs. Install Python 3.11+, extract this repository and double-click `run_ids.bat` (or run it from a terminal in the repository folder). It installs `requirements-ids.txt` into a local virtual environment and writes `results\ids_results.json`, `results\ids_single_results.json` and the matching `_roc_curves.npz` files. Copy those files into `results/` of a full checkout and run `make tables figures paper` to regenerate the manuscript.

Columns that hold vectors written as strings such as `[x, y, z]` are expanded into numeric columns automatically. All remaining numeric columns are used as features. The feature list is stored in `results/ids_results.json`.

## What is deterministic and what is not

- Sizes, the overhead tables, the channel-load curves and the IDS results (for a fixed dataset, configuration, seeds and library versions) are deterministic.
- Timings (`crypto_bench`, `handshake_bench`, `pipeline_bench`, and the IDS inference time) are measurements. They change with the machine, the load and the library versions. The committed `results/*.json` files record the CPU, library versions and parameters of the run that the paper reports. Re-running gives slightly different numbers. The ratios between schemes are stable.
- The text of the paper was written against the committed results. A few sentences state qualitative comparisons (for example that ML-DSA-65 verification is faster than ECDSA verification). If you re-run on a different machine, check those sentences against your new tables.

## Channel model

`src/qshield/overhead.py` computes the offered airtime load of signed beacons from exact message sizes under these assumptions: 38-byte beacon payload, 8-byte timestamp, 4-byte counter, certificate once per second and an 8-byte digest otherwise, 1,400-byte application fragments, IEEE 802.11p 10 MHz PHY with 40 microsecond preamble and header, 8 microsecond symbols, a 10-byte WSMP header and 36 bytes of MAC, LLC and FCS overhead. It ignores contention, collisions and retransmissions, so it is a lower bound on real channel use. The certificate encoding is this project's own, not IEEE 1609.2 ASN.1.

## Tests

`tests/test_protocol.py` runs the handshake for each cipher suite and checks that these are rejected: modified vehicle nonce, modified ciphertext, certificate from an untrusted CA, expired certificate, handshake addressed to a different RSU, replayed beacon, stale beacon, modified beacon payload. These tests exercise the code. They are not a security proof.

## Repository layout

```
src/qshield/       protocol, cipher suites, benchmarks, overhead model, IDS
scripts/           setup, run scripts, table and figure generation, dataset inspection
configs/           dataset and model configuration
tests/             protocol and tamper tests

```
